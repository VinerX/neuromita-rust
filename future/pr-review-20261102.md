## #55: сервер и протокол

Сервер остаётся транспортным Lifecycle: вызывает привязанные API, хранит ограниченные квитанции и наблюдает запросы. Генерация, история и управление персонажами остаются в ядре. `methods` и варианты команд объявлены совместно, dispatch исчерпывающий. Correlation отделяет прямые ответы от фоновых settings-уведомлений. Команды без параметров теперь тоже отвергают неизвестные поля.

Исправление квитанций полезно: завершённая запись может вытесняться за активной, но только после успешного приёма нового запроса. Отказ очереди не теряет старую квитанцию. Приём завершённых клиентских задач имеет приоритет перед новым соединением, что освобождает слот без прежней задержки. Диагностика не выдаёт raw last_error и не представляет доступность TCP как готовность inference.

Блокирующих дефектов в изменённом коде не обнаружено. Повтор между соединениями, auth, гарантии доставки каждого промежуточного статуса и предельное время ожидания медленного клиента не реализованы и честно исключены из контракта.

Интеграция: `git merge-tree` показывает конфликт в `src/server.rs`. Нельзя заменить его файлом PR: у нас дополнительно есть `publish_message`, `react`, `initiate`, расширенные квитанции и выбор пресетов. Каталог, корреляцию и ошибки нужно распространить на эти команды; именно их ещё нет в тестах PR.

Независимо выполнены `cargo test --locked --offline`: **20 passed, 1 live ignored**, в том числе десять TCP-сценариев; rustfmt прошёл.

## #56: импорт, экспорт и запись настроек

Контракт переноса явный: полный документ, строгая десериализация, проверка до записи, целиковая замена, сохранение revision и отсутствие запуска Core/LLM. `SettingsTransfer` имеет закрытое содержимое и проверяемое создание. Две стадии decode не открывают обход проверки: финальная десериализация исходных байтов отвергает повторяющиеся поля.

Атомарная запись использует уникальный соседний temp, create_new, sync, закрытие файла и rename. Тесты проверяют настоящий Windows share lock, невалидный импорт, осиротевшие temp и конкурентную публикацию целых документов. Для остановленного приложения это адекватный объём; межпроцессная синхронизация и power-loss durability явно не обещаны.

**Обязательное условие интеграции:** PR поддерживает только schema 1, тогда как наша ветка пишет schema 2 с `presets` и `characters`. В `src/settings/transfer.rs` задана отдельная константа версии 1; `JsonSettingsRepository::load` заменяется строгим transfer decoder. При переносе этой версии загрузчика текущие документы будут отвергаться как неподдерживаемые, а существующая миграция schema 1 исчезнет. Это несовместимость с нашей новой веткой, не дефект относительно старой базы PR.

Нужна единая константа текущей версии, полный roundtrip всех разделов schema 2 и сохранение явно определённой миграции при обычной загрузке. Решение, принимает ли offline import legacy schema 1 или требует предварительного обновления, должно быть явным. Не использовать отсутствие разделов как повод выбрать скрытые defaults.

`git merge-tree` показывает конфликты в `src/settings/storage.rs` и `src/terminal.rs`. Независимо выполнены `cargo test --locked --offline`: **23 passed, 1 live ignored**, включая 10 файловых и 3 CLI-теста; rustfmt прошёл.

## #58: launcher

Положительная часть: настоящий Child принадлежит LauncherSession; stop и Drop работают с этим Child, а не с найденным PID. Внешние процессы остаются внешними. Identity включает путь и время создания. Установка выбирается явно, candidate проверяется внутри canonical root; автоматического выбора первого произвольного exe нет. Opener получает путь отдельным аргументом. Выделены порты для opener и typed ошибки. Это не нарушает владение Chat/Character/Timeline.

**[P2] Новый config не сохраняется без --candidate.** В [resolve_config](https://github.com/Atm4x/neuromita-rust/blob/3b4df0f0a2e940608bf6d8f555317c29104b2ef1/src/launcher/cli.rs#L99-L123) отсутствующий файл создаёт LauncherConfig с переданным root, затем `changed` инициализируется false. Root уже совпадает, candidate отсутствует, save не вызывается. Команда `launcher session --config NEW.json --install-root DIR`, затем quit завершается успешно без NEW.json. Повторный запуск только с --config снова требует root. Существующий CLI-тест передаёт --candidate и пропускает этот сценарий. Нужно учитывать создание нового config и добавить регрессию без candidate.

Архитектурное замечание, не блокирующий дефект: библиотечный `launcher` содержит интерактивный stdin/stdout loop. При дальнейшем подключении Presenter лучше перенести CLI-адаптер в binary/terminal, оставив в модуле launcher типизированные команды и владение процессом. Синхронные scan/stop/wait не следует напрямую исполнять на потоке будущего GUI.

Немедленный kill при Stop и при выходе из CLI, отсутствие adoption после рестарта и отсутствие GUI обозначены явно. Это продуктовые ограничения реализации, а не скрытая поддержка graceful shutdown или полноценного launcher Presenter. Issue #43 не требует updater/EULA; их отсутствие не считается дефектом этого PR.

`git merge-tree` показывает конфликт только в `src/lib.rs`; это значительно проще переносов #55/#56, но не отменяет функциональную ошибку выше. Независимо выполнены `cargo test --locked --offline`: **23 passed, 2 ignored** (live Gemini и запускаемый тестами helper); rustfmt прошёл. Сама игра и видимый Explorer не запускались.

Ошибка отдельно воспроизведена на собранном CLI без изменения исходников PR: первый session с новым config/root и вводом quit вернул exit 0, файл не появился; второй session только с config вернул exit 1 и `--install-root is required when the config file does not exist`. Существующие тесты зелёные, но контракт первого сохранения нарушен.
