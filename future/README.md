## Принятые границы клиентов и примитивов

Один конечный пользователь работает с одним Core из Unity или через полноценный Launcher/Sandbox-мессенджер; это разные источники контекста, а не независимые пользователи. Unity владеет игровым миром, Sandbox предоставляет собственный контекст дистанционной переписки, SessionTimeline фиксирует события, а MitaView является вычисляемой субъективной проекцией. [Карта с вызовами, владением и границами реализации](root-primitives-and-client-contexts.md).

Роли **Api**, **Lifecycle**, **Handler** обозначают способы доступа, активного существования и адресного управления, а не обязательную трёхслойную структуру каждого модуля.

## Статус документов

Согласованные требования, рекомендации и открытые решения отмечаются отдельно. Документация фиксирует архитектурную модель, а не существующую Rust-реализацию. Примеры типов и контрактов не являются готовыми модулями.

Основная модель изложена в current-model.md. Тематические документы детализируют её. session-timeline-source.md описывает факты исследованной Python-ветки; предлагаемые Rust-решения в нём отделены от этих фактов.

Схемы показывают объекты, владение и контракты обмена. Двусторонние стрелки означают вызов/команду и возвращаемые данные, а не взаимное владение.

## Что изменилось относительно ранних эскизов

- ResponseService переименован в ChatApi; все *Api — статические точки входа одного ядра на процесс.
- CharacterRegistry выдаёт handles владельцев персонажей. Сам Character принадлежит CharacterHandler.
- CharacterHandler предоставляет субъективный CharacterContext и HistoryView. Отдельный ContextBuilder убран.
- PromptMaterial и GenerationInput как обязательная пара контейнеров убраны. Подготовка провайдерского запроса находится в модуле генерации.
- UnityChatEndpoint и UnityIntegration заменены общим ServerLifecycle, работающим по сетевому контракту.
- Presenter — самостоятельная часть приложения, предоставляющая UI команды и наблюдаемые данные.
- Настройки представлены структурами разделов. Каталог из сотен отдельных типов ключей и сотен методов Api не принят.
- Публичное состояние запроса отделено от внутренней фазы принятия эффектов.
- GUI обнаруживает запросы из всех источников через RequestRegistry, затем наблюдает конкретные обращения.

## Точка продолжения

Уточнить состав Message и GenerationRequest; гарантии снимка контекста; согласованное принятие timeline и состояния персонажа; поведение при ошибке принятия; доставку уведомлений о новых запросах при переполнении; техническую историю и сетевые повторы.

## Cargo-проект

В корне самостоятельного NeuroMita-Rust реализован [минимальный набор контрактов](minimal-contracts.md): статические Api, очередь, персонажи и at, генерация и голосовой порт, эффекты, наблюдение, типизированные настройки/binding и TCP ServerLifecycle. Есть консольная привязка к presenter, Tokio full, тесты и vendor для offline-продолжения. Slint, реальный TTS engine, БД и тяжёлый timeline остаются за рамками этого среза. [Запуск](../README.md).
