# Локализация: JSON, читаемый исходный текст и стабильный ID

Реализовано 2026-11-03. Общий модуль: [src/localization](../src/localization/). Он не зависит от Slint, Qt или запущенного ApplicationLifecycle и доступен консольным клиентам без feature `gui`.

## Объявление и перевод

Обычная функция `i18n("launcher.actions.more", "Дополнительно")` возвращает LocalizedText: ID, исходный текст и именованные аргументы. Это описание сообщения, а не уже переведённая строка. Его можно сохранить в presenter и повторно разрешать для любого языка. `Localizer::resolve(locale, &message)` возвращает строку или явную ошибку.

ID описывает назначение и не меняется при редактуре формулировки. Разным значениям одинаковой фразы назначаются разные ID. Русский текст объявляется в коде; отдельно поддерживать русский каталог не требуется.

`message.arg("ver", version)` подставляет именованный аргумент. Аргумент может быть строкой или вложенным LocalizedText: например, уведомление содержит переводимое название действия. При смене языка переводятся шаблон и вложенные сообщения. Набор параметров исходника, перевода и фактически переданных аргументов должен совпадать. Поддерживаются `{name}` и экранирование `{{`/`}}`; числовые спецификаторы Python, plural forms и форматирование дат этим первым контрактом не реализованы. Пользовательские значения не интерпретируются повторно как шаблон.

## Извлечение

[Экстрактор](../localization/extract.rs) вызывается из build.rs и собирает литеральные объявления i18n(ID, source) из каталогов в [sources.json](../localization/sources.json): сейчас GUI Rust и Slint. Для нового frontend каталог исходников нужно добавить туда. Комментарии и строковые литералы с примерами вызовов не считаются объявлениями; поддержаны многострочные вызовы, завершающая запятая, raw strings и Unicode.

Повтор ID с тем же исходником допустим. Разные исходники для одного ID, пустой исходник и неверный формат ID останавливают сборку. Реестр генерируется в OUT_DIR и встраивается в общий модуль. Динамический вызов из адаптера проверяется по этому реестру во время разрешения. Неизвестный ID и несовпадение исходника не маскируются fallback.

Экспорт шаблона и проверка каталогов доступны без GUI:

```sh
cargo run --locked --offline --bin neuromita-i18n -- template
cargo run --locked --offline --bin neuromita-i18n -- check
cargo run --locked --offline --bin neuromita-i18n -- check path/to/Localization
```

Первая команда печатает JSON с ID, исходниками и пустыми переводами. Изменение исходника требует проверки прежних переводов; экспорт не может автоматически определить правильность перевода по смыслу.

## Каталоги

В [localization/python](../localization/python/) без изменения байтов сохранены 15 JSON-каталогов Python и `_template.json`, всего 5 190 488 байт. [Manifest](../localization/python/manifest.json) содержит исходные пути, ревизию и SHA-256. Python-реализация и Qt-реестр callbacks не перенесены. Вместе с русским исходным языком доступны 16 встроенных языков.

Старый формат читается непосредственно: ключ — русская строка, значение — перевод. Новый формат уточняет перевод по ID:

```json
{
  "_name": "English",
  "launcher.actions.more": {
    "source": "Дополнительно",
    "translation": "More"
  }
}
```

`source` — снимок исходника для проверки актуальности. Он получается из экспортированного шаблона. Несовпадение с кодом обнаруживается явно. Пустой translation означает отсутствие готового перевода. Дубли ключей, неизвестные поля ID-элемента, неизвестные ID и несовместимые параметры отклоняются. `_name` задаёт название нового языка в меню.

[Дополнение en.json](../localization/catalogs/en.json) переводит новые элементы и исправляет контекст кнопки меню: More вместо прежнего Custom params. Остальные исходные каталоги сохраняются целиком; это не означает, что все новые Rust-строки уже переведены на каждый язык.

## Политика выбора

FallbackPolicy передаётся явно при создании Localizer. GUI выбирает EnglishThenSource:

1. Перевод по ID выбранного языка.
2. Перевод по русскому исходнику выбранного языка из совместимого JSON.
3. Для языков кроме русского и английского — такой же поиск в английском.
4. Исходный текст сообщения.

Source исключает английский промежуточный шаг. Fallback применяется к отсутствующему переводу известного сообщения. Ошибочный ID, неизвестный язык и устаревший исходник являются ошибками.

## Внешние JSON

GUI принимает явный каталог через `--translations-dir PATH`, начальный язык — через `--language CODE`:

```sh
cargo run --locked --offline --features gui --bin neuromita-gui -- --translations-dir path/to/Localization --language de
```

Каждый файл `<code>.json` задаёт дополнения языка; новый код добавляет язык. Внешние значения перекрывают встроенные. LocaleId нормализует регистр и `_` в `-`; неподдерживаемый код не превращается молча в язык по умолчанию.

Команда «Перечитать переводы» находится в меню глобуса. Кандидат полностью проверяется, затем атомарно заменяет активные каталоги. При ошибке сохраняются рабочий набор, язык и revision. Удалённые файлы перестают переопределять встроенные данные. GUI отклоняет reload, если он удалил единственный каталог текущего языка. Без явно заданного внешнего каталога команда показывает понятное сообщение.

Файлового watcher пока нет: правки JSON применяются командой перечитывания. Переключение языка применяется сразу. Неизменённые каталоги разделяются через Arc; подготовка кандидата не дублирует весь набор переводов.

## Slint и живое обновление

[ui/i18n.slint](../ui/i18n.slint) экспортирует I18n.i18n(ID, source), locale, revision и список языков. Locale/revision являются зависимостями Slint; функция вызывает чистый lookup-контракт Rust. Binding захватывает конкретный Localizer. Общего service locator и приватных API Slint нет. При смене locale/revision существующие bindings вычисляются заново.

Статические подписи находятся в Slint, составные сообщения presenter хранит как LocalizedText. При смене языка сохраняются страница, выбор компонентов и активное уведомление, а их текст разрешается заново. Открытые popup используют тот же адаптер. Пересоздание окна не требуется.

EN/RU дают быстрый выбор, глобус открывает весь список языков и reload. Имена продуктов, версии и демонстрационные даты релизов остаются данными макета. Ошибка разрешения в UI показывается диагностическим маркером.

GUI пока не запускает SettingsLifecycle и не сохраняет язык между запусками. Тип Language в core settings не менялся: он содержит RU/EN. Подключение настоящих настроек должно отдельно согласовать persistence остальных и пользовательских LocaleId; обходного файла настроек этот макет не создаёт.

## Проверка

Контрактные тесты проверяют импорт языков, английское покрытие текущих сообщений, контекстные ID, параметры и вложенные сообщения, fallback, атомарный reload, удаление overlays и конфликты извлечения. Отдельный тест использует настоящий Slint-компонент и общий адаптер: на одном экземпляре меняет RU → EN → DE → EN, затем revision каталога и снова RU. Значения существующих bindings обновляются без пересоздания компонента и без desktop automation.
